# Node.js Concepts Used in the Enterprise AI Assistant Project

This file lists the key Node.js concepts and APIs utilized across the enterprise-ai-assistant codebase (specifically within the backend service `srv/` and the MCP server `mcp/`).

---

### 1. Module System (CommonJS)
*   **Concepts**: Module import and export.
*   **Usage**: 
    *   Imports: `const path = require('node:path')`, `const cds = require('@sap/cds')`
    *   Exports: `module.exports = { main }`, `module.exports = cds.service.impl(...)`

### 2. Built-in Core Modules
*   **Concepts**: Using Node.js standard library modules.
*   **Usage**: 
    *   `path` module (`node:path`) is used to resolve absolute paths relative to the current directory (`path.resolve(__dirname, '..')`).

### 3. Environment Variables & Configuration
*   **Concepts**: Reading environment configuration via the `process` global object.
*   **Usage**: 
    *   Reading custom application variables: `process.env.GROQ_API_KEY`, `process.env.GROQ_API_URL`, `process.env.GROQ_MODEL`.
    *   Reading the server port configuration: `process.env.PORT`.

### 4. Process Lifecycle & Execution Context
*   **Concepts**: Interacting with and controlling the Node.js process runtime.
*   **Usage**:
    *   Changing directory: `process.chdir(path.resolve(__dirname, '..'))` ensures path references are resolved relative to the project root.
    *   Exiting gracefully with custom codes: Setting `process.exitCode = 1` on uncaught async execution errors in `main().catch(...)`.
    *   Module entry checks: Checking if the file is the main executable script via `require.main === module`.

### 5. Asynchronous Programming (Promises & Async/Await)
*   **Concepts**: Non-blocking I/O operations, asynchronous workflows, and Promise chaining.
*   **Usage**:
    *   Frequent use of `async`/`await` for database operations (`cds.connect`, `cds.deploy`), API calls (`fetch`), and file parsing.
    *   Asynchronous IIFEs/functions: `async function main()`, `main().catch(error => ...)`

### 6. Binary & Buffer Operations
*   **Concepts**: Handling raw binary data streams in memory.
*   **Usage**:
    *   Converting base64 encoded document content to raw buffers for parser libraries using `Buffer.from(content, 'base64')` in `srv/chat-service.js`.

### 7. Native Fetch API
*   **Concepts**: Using standard Web APIs directly within Node.js.
*   **Usage**:
    *   Checking availability (`typeof fetch !== 'function'`) and invoking native `fetch` (introduced out-of-the-box in Node.js v18+) for HTTP communication with Groq APIs.

### 8. Web Server & Middleware Architecture (Express)
*   **Concepts**: Creating routing patterns, handling HTTP verbs, parsing request bodies, and handling CORS.
*   **Usage**:
    *   Server instantiation: `const app = express()`
    *   Built-in middleware: `app.use(express.json())`
    *   HTTP method routing: `app.get(...)`, `app.post(...)`
    *   Listening for connections: `app.listen(port, ...)`

### 9. Real-time Streaming & Server-Sent Events (SSE)
*   **Concepts**: Pushing real-time updates from server to client over HTTP.
*   **Usage**:
    *   Writing HTTP response headers manually (`res.setHeader('Content-Type', 'text/event-stream')`).
    *   Flushing headers to initiate a persistent stream connection (`res.flushHeaders()`).
    *   Listening to client disconnect events (`res.on('close', ...)`).

### 10. Memory Cache and Session Storage (Map)
*   **Concepts**: Managing in-memory state for client-server sessions.
*   **Usage**:
    *   Using the JS `Map` data structure (`const activeTransports = new Map()`) to dynamically store, retrieve, and clean up active SSE transport instances using session IDs.
